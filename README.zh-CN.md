# Inkhue

### 一张自带彩色的黑白打印件。

用**任何黑白打印机**打印彩色照片或文档，看起来就是一张普通的黑白页面。<br>
扫描它，Inkhue 就能把颜色还原回来。

## 这是什么

- **任何黑白打印机都能打印**：打出来是一张普通的灰度网点照片。
- **颜色藏在墨点里**：每个小格子里墨点偏向哪个角，就存着这一块区域的颜色。数据和画面逐区域对齐，不是角落里的一个码。
- **扫描就能还原**：任何平板扫描仪或打印一体机，用 600 dpi（最低 400 dpi）扫描，Inkhue 会找到页面、读取墨点、纠正错误、还原颜色。
- **完全开放**：没有密钥、不加密、不用注册账号，格式公开，任何人都能解码。“隐藏”指的是人眼看不出来。

## 怎么用

1. **安装**对应系统的 Inkhue（[下载](https://github.com/TonyD365/Inkhue/releases/latest)）；
2. **HIDE COLOR（隐藏颜色）**：载入照片、图片或 PDF，Inkhue 会生成黑白页，并自动放大到纸张能容纳的最大尺寸；
3. **打印**：用 Inkhue 的打印面板，按 **100% 实际尺寸**打印（默认就是）；
4. **REVEAL COLOR（还原颜色）**：用**灰度、600 dpi**（最低 400 dpi）扫描打印件，可以直接在 Inkhue 里扫描，也可以导入扫描文件。颜色回来后，可以导出为 PNG、JPEG、PDF 等格式。

纸放反了、放歪了、写过字？都没关系。

## 安装

| 系统 | 安装包 | 安装位置 |
|---|---|---|
| macOS（Apple 芯片 / Intel） | `Inkhue-版本-macos-arm64.pkg` / `-macos-x64.pkg` | 「应用程序」 |
| Windows 10/11 | `Inkhue-版本-windows-x64-setup.exe` | 当前用户的程序目录（也可选所有用户） |
| Ubuntu / Debian | `Inkhue-版本-linux-x64.deb` | `/opt/Inkhue`，带应用菜单图标 |

- **macOS**：第一次打开 `.pkg` 会被拦截，到「系统设置 → 隐私与安全性」点「仍要打开」。只需一次，之后自动更新不用输密码。
- **Windows**：出现 SmartScreen 提示时，点「更多信息 → 仍要运行」。
- **Ubuntu / Debian**：`sudo apt install ./Inkhue-*.deb`；扫描需要 `sudo apt install sane-utils`。

## 原理

**1. 格子和亮度**
600 dpi 的打印机只能“打一个点”或“留白”。Inkhue 把打印点分成 **4×4 的格子**（1/150 英寸），每个像素对应一个格子，**打几个点**决定这一格的亮度（0～16 个），和普通黑白网点照片一样。误差扩散把四舍五入的误差分摊给相邻格子，渐变依然平滑。点具体打在格子里哪几个位置，按原图在这一小块里的明暗来选，所以格子内部的边缘和细节也能保留。

**2. 每个格子存 2 比特**
格子里**墨点的重心**偏向四个角中的一个：偏左还是偏右是 1 比特，偏上还是偏下是 1 比特。第 1 步摆点时，只允许选择重心明显偏向目标角的摆法（留有安全余量）。在正常阅读距离下，人眼分不出 1/150 英寸格子里的差别。600 dpi 下**每平方英寸约 45,000 比特（5.6 KB）**，而且数据和画面逐区域对齐。

**3. 文档：白纸也要带数据**
一个点都没有（纯白）或 16 个全满（纯黑）的格子没有“偏向”，存不了数据。照片里这样的格子很少，笔记、练习纸却大部分是白纸。所以当一页里这样的格子超过 20% 时，Inkhue 让**每格保留 1～15 个点**：白纸上每格有一个很浅的点，同样能带数据。文件头里有个标记，解码时会把亮度校正回来，白纸还原出来仍是白的。

**4. 颜色数据**
- 图像分成亮度和颜色（Cb/Cr）。亮度就是打印出来的墨点本身；人眼对颜色细节不敏感（JPEG 和电视信号也利用了这一点），所以颜色按 **1/8 分辨率、6 比特**存储；
- 一个小**文件头**（格式版本、颜色分辨率、标记）用纠错码保护，并存 48 份；
- 颜色数据分成 **Reed-Solomon 纠错块**（每块 255 字节，最多能纠正 16 个错误字节），并在页面放得下的范围内**重复多次**，通常是 9 份；
- 每个比特再按**固定、公开的置乱顺序**分散到整页各处。污渍、折痕、笔迹只会让每一份都损失一点点，而不会毁掉某一整块区域；重复的数据也不会形成看得见的花纹。置乱的种子是格式的一部分，永远不变，没有任何秘密。

**5. 边框和定位**
页面四周依次是：白边、**2 格宽的黑框**、上边和左边的**计时轨道**（黑白交替的格子）、一圈白色间隔。
1. 扫描图里最大的深色轮廓就是黑框。四条边用抗干扰的直线拟合求出（碰到黑框的笔迹会被忽略），再求交点，得到精确到亚像素的四个角；
2. 用透视变换把页面摆正，校正歪斜和梯形变形；
3. 计时轨道一黑一白交替，相当于一个“波”。从整条轨道的频谱测出波长，就得到格子尺寸，误差约 0.1%。在 400 dpi 下，每格只有约 2.7 个扫描像素，也能测准；
4. 如果文件头校验不通过，就依次尝试附近的网格尺寸，再把扫描图转 90°、180°、270°（纸放横了或放反了），由文件头的纠错校验确认哪个是对的；
5. 用三次插值把页面重新采样到“每个打印点一个像素”。

**6. 读取格子和纠错**
每个格子测出墨量（亮度）和墨点重心（2 个“软”比特：不只是 0 或 1，还带有可信程度）。去掉对齐不完美造成的缓慢偏差后，把每个比特的所有副本按可信度相加，再交给纠错码。仍然纠不过来的块，对应的画面区域**保持灰色**，不会填上随机颜色。

**7. 神经网络**
直接解码出来的照片有颗粒感，颜色也偏糊（毕竟只有 1/8 分辨率）。一个约 100 万参数的 **U-Net** 会**逐个打印点**读取扫描件，并结合解出的颜色，输出 **2 倍分辨率**的彩色照片（600 dpi 打印对应 300 ppi）：去掉网点颗粒，修正墨粉扩散，读出第 1 步藏在格子里的细节，并按亮度边缘锐化颜色。它用 DIV2K 的 800 张照片和合成文档（彩色文字、高亮、图表）训练，训练数据都经过模拟打印扫描，打印机和扫描仪的参数随机变化。发布时是 4 MB 的 ONNX 模型，在 CPU 上大约 1 秒完成。

**8. 测试方法和局限**
模拟器会模拟墨粉扩散、着墨不均、纸张噪点、旋转、梯形变形、光学模糊、色调曲线、传感器噪声和 JPEG 压缩，每次改动都按几种强度跑一遍 benchmark。
- **扫描分辨率**：数据存在一个个 1/600 英寸的点里。400 dpi 时每个点约 0.7 个扫描像素，这是能稳定工作的最低分辨率；300 dpi 时点就糊在一起了。要支持 150～300 dpi（或手机拍照），需要更大的格子，已列入计划；
- **细小的彩色文字**会比原件淡：8×8 格子的颜色样本里，笔画和周围的白纸混在一起了。文档调色板已列入计划；
- **缩放**：不是 100% 打印会打乱打印点，颜色通常就解不出来了。

**和二维码、数字水印的区别**：它们只能存几个字节到几 KB，要么放在图像旁边，要么只是一个微弱的标记。Inkhue 存储的是**画面每个区域的信息**，而打印件本身仍是一张清晰的照片。

## 测试结果（模拟打印扫描）

| 条件 | 解码成功 | 色差 ΔE | 细节 PSNR @2× |
|---|---|---|---|
| 普通 | 100% | 2.52 | 29.2 dB |
| 600 dpi 扫描 | 100% | 2.91 | 28.1 dB |
| 400 dpi 扫描 | 100% | 3.25 | 27.1 dB |
| 页面上写过字 | 100% | 3.31 | 22.9 dB |
| 恶劣（打印扫描质量都很差） | 80% | 6.65 | 21.9 dB |

ΔE 约为 2 时肉眼刚好能察觉。以上为模拟结果，欢迎用真实打印机和扫描仪测试，并用 Issue 的「🖨️ Print / scan report」模板分享结果。

## 使用建议

- 按 **100% 实际尺寸**、打印机原生的 **600 dpi**、普通纸打印；激光打印机效果最好，关闭省墨模式和照片增强。
- 用**灰度、600 dpi**（最低 400 dpi）扫描，关闭锐化和去网纹，整个黑框都要在扫描范围内。
- 印得越大，还原越清晰，抗损能力也越强。

## 路线图（2.0）

- **分块自定位**：一页上可以混排 Inkhue 图像和普通文字，每一块独立解码，损坏的块保持黑白；
- **文档调色板**：细小的彩色文字也能还原成原本的颜色；
- **大格子模式**：支持 150～300 dpi 扫描，以后还能用手机拍照还原；
- **真实打印机校准**：根据社区的实测报告持续改进。
